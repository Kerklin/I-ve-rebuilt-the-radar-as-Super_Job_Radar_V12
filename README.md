# Super Job Radar V12

Every 6 hours GitHub reads **23 job sources**, keeps the vacancies that fit Damir's profile (English and Bosnian/Croatian/Serbian), checks each one for eligibility blockers, and publishes **one web page**.
No AI, no packages, no paid services. The workflow uses 2 actions, both on Node 24, and is pinned to Ubuntu 24.04.

## The 8 files
| File | What it is | Edit it? |
|---|---|---|
| `super_job_radar.py` | The program | Rarely |
| `profile.json` | **What** to look for: keywords, penalties, bonuses, cut-off | Yes |
| `sources.json` | **Where** to look: 23 sources, each with a manual link | Yes |
| `test_cases.json` | Job titles that must / must not appear | When a result is wrong |
| `super_job_radar.yml` | The schedule (a copy lives at `.github/workflows/`) | No |
| `README.md` · `AGENTS.md` · `CLAUDE.md` | Guide · AI rules · Claude Code entry | — |

Generated by each run: the web page, `jobs.json` (memory) and the run Summary.

## B. ReliefWeb setup (once, 5 minutes + waiting for approval)
ReliefWeb's website and RSS give automated readers an empty page, so V12 reads the official API instead. The API needs a free **approved appname**.

1. Request the appname at **https://apidoc.reliefweb.int/parameters#appname** (short form). Use your name or organisation, the purpose and random characters, for example `DamirHadzic-JobRadar-7Kq2`. Purpose: *personal job search, 8 requests per day, no redistribution*.
2. Wait for ReliefWeb's approval email.
3. **Settings → Secrets and variables → Actions → New repository secret**:
   - Name: `RELIEFWEB_APPNAME` (exactly like this)
   - Secret: the approved appname exactly as approved, with no spaces or quotes
4. **Actions → Super Job Radar → Run workflow** → Source health: **ReliefWeb** and **ReliefWeb Balkans** change from SETUP to OK.

What the program sends (you don't need to type this; it's here for checking):
```
POST https://api.reliefweb.int/v2/jobs?appname=<RELIEFWEB_APPNAME>
{"limit": 200, "profile": "full", "sort": ["date.created:desc"],
 "query":  {"value": "construction OR engineer OR infrastructure OR rehabilitation OR shelter OR architect OR procurement", "operator": "OR"},
 "fields": {"include": ["title","url_alias","url","date.closing","country.name","source.name","body"]}}
```
"ReliefWeb Balkans" sends `"filter": {"field": "country.exact", "value": ["Bosnia and Herzegovina","Serbia","Montenegro","Croatia","North Macedonia","Albania","Kosovo"], "operator": "OR"}` instead of `query`.
The appname is masked in every error message and never written to the page or to `jobs.json`.

| ReliefWeb status | Meaning | Fix |
|---|---|---|
| SETUP | The secret is missing | Step 3 |
| FAIL 400 "Missing appname" | The secret is empty or wrongly named | The name must be exactly `RELIEFWEB_APPNAME` |
| FAIL 403 "not using an approved appname" | Not approved yet, or mistyped | Wait for the email; re-paste the value |
| OK | Working | — |

## C. Live-source verification and repair (after every change, and weekly)
Run it **in GitHub** (Actions → run → Summary → *Source health*). On your PC run `python super_job_radar.py --check` (or `--check GIZ` for one source). The PC result can differ from GitHub's because some sites block one network and not the other.

| # | Check | Pass when | If not |
|---|---|---|---|
| 1 | Status column | OK, or SETUP for ReliefWeb only | Follow the **How to fix** text on that row |
| 2 | Items > 0 for every OK source | The site was read | "OK but 0 items" → open **Manual**; the list format has changed |
| 3 | Matches look right | Spot-check 3 titles per source against **Manual** | A missing or wrong job → add it to `test_cases.json`, then adjust `profile.json` |
| 4 | Deadlines | Pick 3 vacancies and compare the date on the page with the vacancy | Wrong date → send the source name and one vacancy link |
| 5 | NOT ELIGIBLE rows | The reason matches the vacancy text | Wrong blocker → send the title and the link |
| 6 | `fails_in_a_row` in `jobs.json` | Below 3 | 3 or more → repair the source, or set `"off": true` and use **Manual** |

**Repair rules:** repair a source only after **3 failed runs in a row**, since single failures are often temporary. Never work around robots.txt, logins or anti-bot pages. After any edit, run **Run workflow** once and repeat checks 1–2.

| Error contains | Cause | Repair |
|---|---|---|
| 401 | Token or session rejected | Wait one run; if it repeats, `"off": true` + Manual |
| 403 / empty page / robots.txt | The site refuses robots | `"off": true` + Manual. Do not bypass |
| 404 / 410 | The address moved | Find the new list/feed address on Manual; update `urls` |
| 0 vacancies / 0 job IDs | Layout changed or JavaScript-only page | Update `job_link_contains`, or `"off": true` |
| timed out / 5xx | The site is temporarily down | Nothing; it retries next run |

## Reading the page
**OK** = no blocker found · **CHECK** = open the vacancy (deadline or eligibility unclear) · **NOT ELIGIBLE** = internal only / other nationals / EU only / local post outside BiH / deadline passed (greyed) · *NEW* = last 24 h · *old data* = the source failed this run (kept up to 7 days).
